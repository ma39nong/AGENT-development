## 路线固定

保留现有五阶段示范、四种π0.5 Prompt。云Qwen做离线初标，本地Qwen负责最终在线计数、历史查询和Prompt选择，π0.5执行已有技能。数量与调整时机不固定；不新增细阶段训练作为前提，不要求用户从零手工标204条。

先用既有subtask与自动计数候选准备数据；发现真实错误后再补标签。摘离与成功投放分别记录，避免混用；原始目标没有记录则为空，不根据实际摘取总数倒推用户指令。

## 本轮实际运行

- 原始204条已有索引；本轮仅用5条train，未读取封存测试视频、未把验证或测试数据作为训练初标样例。

- 30秒连续分块，重叠3秒，覆盖每条录像全长区间。实际请求是带时间的采样多图，不是上传全部30fps视频帧；采样可能漏掉短事件，后续需局部加密。

## 已抽查到的真实问题

1. 早期提示词把7.5秒拿起整串的画面当作单颗摘离；修改了定义，但其他录像仍有整串/单颗混淆候选，需要继续核查。
2. 当前提示词将第一条24秒判为成功放盘；原始左腕画面此时仍持果位于盘上方，27秒画面已空手。因此24秒不能作为在线成功确认时刻，准确释放时间需加密复核。
3. 自动提出的observed_adjustments也属于未核查建议；当前仍以已有subtask提供示范阶段，不能用模型输出覆盖原阶段标签。

证据图与部分视觉抽查记录位于runs/api-teacher-pilot-v2/evidence-audit.jpg、runs/api-teacher-pilot-v3/first-delivery-audit.jpg和visual-audit.json。没有对5条全部事件做完视觉核查，不能报告准确率。

## 接下来的确定顺序

1. 在这5条上把候选事件映射回原三路视频，针对放盘候选与不确定区间加密取帧；复核单颗事件、纠正时间、关联跨块重复，形成少量可信计数记录。主要由开发端完成初标和复核，不要求用户逐条细标。
2. 继续使用已有subtask作为阶段监督，将整串拿起与单颗事件区分；事件时间落在非采摘阶段只提示复核，不默认已有边界绝对正确。
3. 检查候选生成质量后扩大到剩余train。204原划分为train151/val21/历史测试12/封存测试20；绝不将204全部混作训练。验证标签需要独立复核；封存测试不参与提示词和训练调参。
4. 按源录像形成LoRA样本：截至当前的三路画面、相关历史、目标参数→新增计数事件、当前进度、下一Prompt与条件。没有原目标的录像不伪造真实任务目标；合成目标上下文单独标记，也不等于有提前放回动作示范。
5. 先做本地4B基线对照和小规模LoRA，评价计数漏报、误报、重复、时间证据和决策。选择LoRA目标依据真实错误，不假定微调自动加快推理。
6. 在线回放仅提供截止时间前画面。整段视频事后确认不能提前成为模型输入或任务记忆；验证达到目标后是否赶得上下一次不可撤销抓取。
7. 部署旁路比较建议与实际，再按已验证技能能力接入四种Prompt切换。当前未启动机器人、未开放自动控制、未修改π0.5训练或部署仓库。
