# 云端 Qwen 连续短视频回放测试

## 目的与已授权范围

用户要求继续测试云端 API，以视频片段输入代替客户端多张抽样图片。此轮进行 Flash 与 Max 各最多 63 次请求，共最多 126 次，不自动重试。仅测试粗阶段识别与响应时间，不计数、不调用机器人、不改变 π0.5 或 V-JEPA。先完成本批分析，再决定是否有必要进行新的付费实验。

## 输入与时间契约

使用之前已核查的 train 录像 `b0f7213da83547b99aac45f6438b511e`，头部原始 cam0，3779 帧、30 FPS、125.967 秒；原视频与粗标注 SHA 校验。只用此条已知开发样本，不涉及 32 条留出测试或额外五条新录像。

源视频每 2 秒设置一次观测截止点，外加片尾，共 63 个点。从原始视频物理裁剪截至当时最近 8 秒的 MP4，保持原尺寸、帧时钟，H264 CRF18 重新编码，检查帧数与 FPS。最后源帧严格为截止帧减一，不包含未来真实画面。前几次不足 8 秒时输入已有前缀。

发送 `video_url` 的 MP4/Base64，无 image/image_url 消息、不进行客户端采样图片或多路拼图。服务端采样仍由提供商决定，不能根据原文件 30 FPS 或 video_tokens 声称模型逐帧读取 30 FPS。源 MP4 有视频帧不等于已建立持续视频连接。

模型 `qwen3.8-flash` 与 `qwen3.8-max`，关闭深度思考，非流式文本响应，最多 160 输出 token。沿用既有粗阶段观察规则，去掉关于历史图片的说明。当前目标为 cutoff 时刻的 phase、可选序号、uncertain 与一句依据，不提供标准边界、完整视频时长或标准答案。历史最多两条，来自同模型先前实际返回的未核实候选；只有估计返回源时刻不晚于当前 cutoff 的候选才进入输入。

粗标注仅在请求完成后对照评分，不能通过上下文注入。候选历史允许错误并明示未核实，没有手动纠正。

## 此轮回放的限制

这是离线连续源时刻回放，不是提供商原生持续视频会话。HTTP 请求按顺序完成，不按墙钟强行并发每两秒发起，因此未模拟真实队列积压或丢弃过期请求。历史可用性使用 cutoff＋实测准备与完整请求耗时估计，属于独立源时刻发起假设。若耗时超过 2 秒，真实部署不能默认所有请求都能按这个频率串行完成。

API 时延从发送请求到完整响应，包含 HTTP 传输与响应等待；request_cycle 包含物理裁剪、MP4 编码检查、Base64/请求准备与完整调用，仍不含事件证据可见等待、真实摄像头缓存/调度、机器人技能生效。

每处交接报告该阶段开始后首次判对的观测截止时刻、估计结果返回时刻及提前误判，不能把首次判对当成稳定确认或实机截止时间保证。单条录像不能估计总体准确率、稳定尾延迟或证明已支持动态数量切换。

## 格式与视觉判断分开记录

模型有时返回包裹在完整 Markdown JSON 代码围栏内的对象。原始在线观察器严格解析 JSON，围栏回答被记为无效且未进入该次真实候选历史；所有原始回答保留。

汇总脚本另行只移除完整 JSON 围栏再评分，报告可恢复的阶段识别结果。这个后处理不改写旧历史，也不能声称如果运行时解析宽容，后续候选序列仍必然相同。截断、杂文或非法字段不自动“修复”为有效回答。
