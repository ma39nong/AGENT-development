## 实际输入

## 不重新编码及因果检查

前缀采用 `-c:v copy` 复制原编码视频数据，不解码后重新编码。因截断 GOP 会有重排序帧，使用约 0.2 秒裁剪余量，实际结束可能略早于名义时间。逐个解码验证 FPS/帧数，读取帧显示时间戳确定最后源帧，并与原视频对应帧逐像素比较；要求最后源帧严格早于名义截止时间。评分用实际结束源帧，不强称精确 10.00 秒等。

初版预检把解码帧数量误当成最后源帧序号，因重排序导致检查失败，**没有发送 API 请求**。保留 `runs/cloud_full_prefix_baseline_20261123_v1/status.json`。修正为根据显示时间戳找源帧并核对像素后，使用全新 v2 目录运行，13 个前缀全部通过预检。截断 GOP 可能省略少量尾部重排序帧；不把这种前缀声称为可按任意帧无损精切的连续流实现。
