# 固定路线集中验收：云端 Max＋结构化短输出＋技能完成条件＋交接门控

用户已限定本轮范围：仅固定交接与原截断案例，不扫模型、提示词、窗口或训练参数。当前分支 qwen-harvest-agent，本批付费请求已完成并停止，无真实机器人调用。

## 唯一配置与案例

qwen3.8-max，enable_thinking=false，response_format=json_object，max_tokens=96。系统提示词固定为 `prompts/cloud_max_handoff_zh.txt`，只输出 completion、decision、next_skill 三个枚举字段，严格解析，额外解释、代码围栏或截断均不自动修复。

11 个固定案例各重复两次，共 22 请求，无重试：原先名义 30/40/80 秒的三个截断前缀（复用旧文件并验证 SHA）；四处粗交接前后各约一秒的八个因果累积前缀。仍用同一已知 train 录像、头部 cam0，前缀视频数据复制、不重新编码，源帧时间与像素核对。腕部画面仅在测试后人工复核中查看，未发送给模型。

输入执行上下文明确为模拟：当前技能、阶段 epoch、planned_next 和 stop_requested。原截断案例 stop_requested=false；交接案例 stop_requested=true。采摘完成必须结合程序结束请求，不能把单颗投放当作整个采摘技能结束；本轮不推断果实数量。这个任务不再是无上下文的阶段分类，不能直接与此前阶段准确率作单因素比较。

完成条件：拿起后持稳；结束采摘请求后左手释放到盘、空手且停住；调整后右手持串停稳；放回后释放。视频已发生后续动作时应标记 scene_changed，执行器重核实际状态。粗标注记录的是下一阶段运动起点，不能直接将其前一秒标成“未完成”、后一秒标成“刚完成”。

## 实测结果

- 严格短 JSON：22/22；均正常 stop，无截断和额外解释。
- 原三个截断案例：6/6 输出完整；都没有提议交接。
- 交接前：8/8 提议 handoff、完成为 yes；不能仅因接近粗边界就认定这些完成判断正确。
- 交接后：8/8 仍按旧技能提议 handoff，scene_changed 为 0/8。下一技能已开始的案例未被模型自行识别为旧执行状态，**这一集中验收项未通过**。
- 两轮 decision/next_skill 一致 11/11；completion 一致 10/11（80 秒案例 no/unknown 不同）。重复一致不是视觉正确率。
- API 完整响应中位数 2.775 秒、最大 10.692 秒；19/22 的观测至返回周期超过离线筛查阈值 2 秒。2 秒只是本轮筛查参数，未由机器人实际动作截止时间确定，不宣称实时保证。

## 门控实现及其实际限制

`scripts/handoff_gate.py` 是无控制通信的纯判断组件。只有严格有效结果、任务/技能版本匹配、连接正常、stop_requested=true、确认安全交接点、无已排队动作、转换能力已验证、观测未过期、completion=yes 且请求目标等于当前计划，才返回请求有资格执行。

单元测试覆盖可放行的正例，以及无效结果、版本变化、断连、缺安全点、未完成动作、未验证转换、过期结果、错误目标、缺失状态等拒绝条件。通过不代表机器人具备安全暂停或动作取消能力。

22 条回放使用**故障夹具**而非实机回执：交接后的模拟 epoch 已变化，8/8 旧请求被 stale_execution 拒绝；交接前没有真实安全点/转换能力回执，8/8 因 no_safe_point 拒绝；原截断案例没有结束请求，6/6 被 no_stop_request 拒绝。全部阻断是夹具预期行为，**不是22个场景端到端验收通过，也不证明真实控制器已保持、退让或停止**。

真正接部署时，门控必须位于下一条不可撤销动作发出之前；它不能只限制换 Prompt，却允许旧 harvest 在等待期间发起新采摘。当前未接 π0.5 动作队列/取消或保持接口，缺少这条执行闭环就不能开放自动控制。迟到结果只归档或重新观察，不以“模型答对了”绕过版本与新鲜度检查。
