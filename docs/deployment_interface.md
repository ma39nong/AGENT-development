# Agent与部署接口草案 v0

状态：待实现；不是已上线API。先对齐字段语义，再确定传输方式和完整schema。

## 边界

部署端拥有相机/ROS、动作进度、运动权限和实际技能状态。本仓库拥有Agent推理、事件证据账本和计划。
高频控制不依赖逐次HTTP规划回复。条件监控耗时也需要测量，不能假定存在即时判定。
部署适配器不复制一套独立计数真值；使用带版本的账本快照/更新。

## 部署→Agent

- task_id、task_revision、用户目标和顺序约束。
- observation_id、相机源时间、采集/到达时间、时钟域及同步质量。
- 三路真实画面；head_crop关联head源帧及坐标、框来源/目标时间、有效性和处理版本。
- requested_skill、active_skill、skill_revision、运行/等待/故障状态。
- 当前执行进度、已承诺动作前缀、可交接能力和实际生效回执。
- 允许技能及转换能力表，缺失能力不得由模型假设支持。

源相机时间与本机单调时间保留各自时钟域，未经映射不能直接相减计算跨机延迟。
大图/视频在本机或受控存储引用，传输协议确定后明确生命周期，不将敏感密钥传入消息。

## Agent→部署

- decision_id、task_revision、plan_revision、基于的skill_revision与观测截止时间。
- 事件建议/纠正及原始证据引用，确认/未知状态与账本版本。
- 请求技能、目标对象线索、触发条件、完成条件、异常分支。
- 计划有效范围；所需能力缺失、证据不足时返回不可执行原因。

动作请求由部署端核验任务/技能版本、输入新鲜度、能力和待处理果实；接受不等于生效。
条件采用可校验的结构化表达和已支持的谓词，不执行任意生成代码。

## 生效与异常

回执包含decision_id、accepted/rejected/pending/applied/failed、实际技能版本、原因及单调时间。
相同decision_id幂等。冲突计划、过期请求、乱序和重复分别测试。
旧任务回复不能控制新任务；迟到历史事件经核查可补账，不能自动复用其旧动作。
断连后的保持/退让/停止由部署端能力决定；恢复需要重新同步，禁止旧计划自动开动作。

## Fovea专用边界

Fovea的used_box/next_box、源查询和目标执行步归部署端管理。
Agent消费实际使用的裁剪及其来源，不直接推进框会话或改变训练规定的偏移。
技能变化时由部署端处理旧推理、动作和框失效，再回报新会话与实际技能。
