# Qwen 采摘 Agent 开发要求

日期：2026-11-21。状态：开发规格；不代表能力已实现或实机验收。

## 1. 任务目标

- 支持“摘 N 颗，必要时调整后放回”，轮次和调整时机不预设。
- 用户明确指定“先 A 颗、调整、再 B 颗”时，遵守该约束。
- 任务开始前显示解析结果；目标修改生成新任务版本，Qwen 不自行改总目标。
- 分开记录摘离、成功投放和待处理数量。第一版成功标准为指定收集盘中的新增确认投放，最终还要验证番茄串放回。
- 已摘离但未确认投放的果实占用待处理名额，不允许因尚未计成功就再摘一颗。

## 2. 技能及能力边界

沿用现有五阶段示范：拿起→采摘→调整→采摘→放回；对应拿起、采摘、调整、放回四种π0.5 Prompt。
不新增细阶段训练作为前置条件。Qwen根据计数、任务约束与视觉选择Prompt及切换时机。

动作仍使用拿起、采摘投放、调整、放回四种Prompt，可循环、分支，不限定两轮；补充观察是调度状态，不新增动作Prompt。
执行技能与允许转换由部署端能力表提供，不允许 Agent 凭空创造技能。
首次采摘直接放回、重复调整、带剩余果实放回等路径分别验证。
现有连续采摘阶段不等于“一次调用一颗”；需识别实际可交接位置，必要时补充单颗技能训练。

## 3. 视觉输入

三路相机：头部、左腕、右腕；第四路是头部真实画面的局部裁剪，不是新相机。
每份裁剪记录原图源帧/时间、尺寸、框、缩放、框来源、有效性和版本。
普通模型的定位/跟踪裁剪与 Fovea 策略预测框裁剪分开标记，不能不核对权重契约就互换。
预测框裁剪当前真实画面可以作为当前证据；生成的未来图像不能作为已完成事件证据。
在线处理不得使用未来真实帧。局部图无效时回看原图或明确未知，同源图不重复计数。
Agent 查询附加局部图不直接覆盖动作模型使用的 Fovea 框。

## 4. 视觉记忆

近期缓冲保存同步视觉与执行状态；事件账本保存尝试、证据和结果；关键视觉历史保存可复核原帧/短片段。
关联任务、尝试、源时间和对象线索，不确定身份不得编造稳定对象 ID。
支持查询最近成功、重复事件、失败重试、调整前后变化和未决证据。
不重复输入全部历史。向量用于检索，保留原始证据；任意编码不直接作为 Qwen 或 π0.5 的内部特征。
Fovea 的跨查询框状态与 Agent 长期视觉记忆是不同概念。

## 5. 事件计数与计划

尝试状态至少覆盖抓空、已摘离/运输、确认放盘、掉盘外、未知。
成功事件只计一次，去重需结合尝试和视觉源时间，不能只按请求 ID。
第一版上一颗结果未清楚前不启动新采摘，允许当前待处理果实完成投放。
Qwen 提出事件与计划更新，程序核验格式、引用、时序和版本；程序核验不能被当作视觉准确性证明。
确认事件需要改判时追加带理由和证据的纠正记录并重算进度，不允许计划静默覆盖历史事实。
未达目标且可操作时继续；有证据需要调整时调整；达标且无待处理果实、放回前提成立时放回。
未知触发补充观察；连续失败和无进展需有限次数/时长约束，数值通过基线确定并显式配置。
计划支持条件分支、失效与修改；不执行模型生成的任意机器人控制代码。

## 6. 两类异步与截止时间

部署端负责动作异步、已承诺前缀、执行反馈和预测框目标时刻；本仓库负责决策与记忆时效。
当前 Fovea 原型是完成15步后提交下一框的串行链，不能将后台线程等同于 RTC 完成。
记录观测、框目标、推理返回和实际执行进度；不能将未来框提前用于错误时刻的新图像。
输出50步动作不代表可无条件继续执行剩余动作来遮盖延迟。
任务截止时间：新抓取不可撤销起点；它与15步动作块边界不一定相同，必须实际标定。
记录事件到可见证据、采样、处理、推理、传递、接受和交接生效的完整延迟，首字不是决定。
接近目标且结果未确认时，不放行新采摘。等待、退让、停止需部署端验证，不假设暂停保持可用。
测试 Qwen/PyTorch 与 π0.5/Fovea/JAX 共用GPU的显存、排队和两边长延迟；不擅自改对方环境。

## 7. 技能交接

提议→版本和能力校验→接受→处理已承诺动作→新观测接入→实际生效确认。
分别显示 requested_skill 与 active_skill；未收到确认不认为完成切换。
迟到事件可在同任务内核查补账；旧状态动作不能直接执行；旧任务结果只归档。
切换技能时旧动作与旧框按部署契约失效。断连或重启后不得凭旧计划自动恢复动作。

## 8. 模型、数据与LoRA

先测本地 Qwen3-VL-4B-Instruct，不开深度思考，再根据错误选择训练目标。
LoRA覆盖事件证据、记忆更新、调整判断、下一技能和条件计划，先冻结视觉编码器。
Qwen LoRA 与 π0.5 动作/Fovea框联合训练分开配置，不先做跨模型联合损失。
数据记录实际裁剪来源；包含不同目标、路径、失败、遮挡、重复和未知，不能只学标准顺序。
按完整录制及源录制派生关系分组划分，所有重叠窗口、裁剪版本不得跨训练测试。
既有阶段标签不能直接充当投放、调整或分支决策真值；伪标签需标记并人工核查测试标签。
现有subtask可作为已示范阶段与衔接监督。先由云API生成计数候选并复核，不要求全量手工细动作标注；事后识别标签转在线样本前需因果回放。
原始数据不覆盖，模型、录像、密钥和训练产物不进入 Git。

## 9. UI和接入

本仓库输出服务接口，部署仓库保留观测、技能执行和UI适配器；不把LoRA环境装进部署环境。
Qwen与V-JEPA独立选择，普通四路与Fovea是动作模型路线，UI只开放验证过的组合。
显示目标/约束、确认/待处理/未知、实际与请求技能、计划版本、数据年龄、延迟和裁剪状态。
默认离线/只建议，自动执行需验证后单独开放。日志禁止保存密钥。
部署旧Qwen代码先保留，按接口渐进迁移；不能两套记忆账本同时作为控制真值。

## 10. 实施与验收

1. 固定接口与源时间契约；独立环境跑通基础推理与真实多路样本。
2. 构建人工核查集与基础模型评测；记录误报、漏报、弃权和时序证据质量。
3. 小样本LoRA验证保存/重载与资源，再扩大训练；测试集冻结。
4. 离线执行模拟器与因果回放：只提供当时已到达数据，注入延迟、重复、乱序、断连和切换。
5. 与部署Fovea异步工作按接口并行；未通过的异步模式不开自动控制。
6. 真实观测旁路，仅记录建议；之后逐项开放已验证技能转换。
7. 完整任务报告数量、多摘/漏计/重复、约束遵守、调整质量、过期误执行、交接截止时间、等待与总耗时。

对照保留普通四路/Fovea、手动/Qwen，Fovea串行作为参考；不将同时改变多个模块后的收益归因于单一模块。
有限测试零多摘不代表数学保证。报告明确独立录像数、重复次数、未覆盖路径和模型版本。

交付：代码、环境与模型版本、数据清单与划分、训练配置、回放及现场评测、允许技能表、部署回退说明。
